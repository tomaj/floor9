PERF01 / 07

Performance audit

Audit výkonu

Is the app as fast as it can be - server, data layer, and the React render path.

Beží appka tak rýchlo, ako sa dá - server, dátová vrstva aj render v Reacte.

Prompt
Audit this application for performance and validate we're doing things right, end to end. Check the real code, not assumptions.

Focus on (but don't stop here):
- Database / server calls: query efficiency, missing indexes, over-fetching rows or columns, missing pagination.
- N+1 query patterns anywhere in the data layer.
- Redundant or duplicate backend/DB calls - the same data fetched more than once, missing caching or memoization.
- React: how we manage state and re-renders. Unnecessary re-renders, missing useMemo/useCallback/React.memo, state placed too high in the tree, heavy components.
- Time to first meaningful render: bundle size, code splitting, lazy loading, requests blocking the critical path.
- How we load resources (images, fonts, scripts): eager vs lazy, caching headers, CDN usage.
- Request waterfalls that could be parallelized or batched.

For each finding: point to the exact file / component / query, explain the impact, give a concrete fix, and rank everything by impact-to-effort. The goal is for this app to perform as well as it possibly can.
Pozri sa na výkon tejto aplikácie a zvaliduj, či to máme spravené dobre, od servera až po render. Kontroluj reálny kód, nie predpoklady.

Zameraj sa hlavne na (ale nekonči pri tomto):
- Volania do databázy / na server: efektivita dopytov, chýbajúce indexy, naťahovanie zbytočných riadkov a stĺpcov, chýbajúce stránkovanie.
- N+1 dopyty kdekoľvek v dátovej vrstve.
- Zbytočné alebo duplicitné volania na backend/DB - tie isté dáta tahané viackrát, chýbajúci caching alebo memoizácia.
- React: ako pracujeme so stavmi a re-rendermi. Zbytočné re-rendery, chýbajúce useMemo/useCallback/React.memo, stav uložený privysoko v strome, ťažké komponenty.
- Čas do prvého zmysluplného vykreslenia: veľkosť bundlu, code splitting, lazy loading, requesty blokujúce kritickú cestu.
- Ako načítavame resources (obrázky, fonty, skripty): eager vs lazy, caching hlavičky, využitie CDN.
- Vodopády závislých requestov, ktoré by sa dali paralelizovať alebo dávkovať.

Pri každom náleze: ukáž presný súbor / komponent / dopyt, vysvetli dopad, daj konkrétnu opravu a zoraď všetko podľa pomeru dopad/námaha. Cieľom je, aby appka bežala čo najlepšie.
FUNC02 / 07

Functional coverage vs PRD

Funkčné pokrytie voči PRD

Does the implementation actually match the PRD - every screen, every step, every state.

Sedí implementácia naozaj s PRD - každá obrazovka, každý krok, každý stav.

Prompt
Verify in depth that we've implemented everything in the PRD. Treat the PRD as the source of truth and go feature by feature.

For every requirement in the spec, check:
- The screen it describes actually exists and is functional.
- The step / flow does what the spec says - the behaviour matches, not just "a screen is there".
- Edge cases, empty states and error states from the PRD are handled.
- Nothing from the spec is silently missing or only half-implemented.

Deliver a coverage table: PRD requirement -> implemented? (yes / partial / no) -> where in the code -> the gap, if any. Cite concrete files. Flag anything built differently from the spec, even if it works.
Over do hĺbky, či máme implementované všetko, čo je v PRD. Ber PRD ako zdroj pravdy a choď feature po feature.

Pri každej požiadavke zo špecifikácie skontroluj:
- Či obrazovka, ktorú popisuje, naozaj existuje a je funkčná.
- Či krok / flow robí to, čo hovorí špecifikácia - správanie sedí, nie len "obrazovka tam je".
- Či sú ošetrené hraničné prípady, prázdne stavy a chybové stavy z PRD.
- Či nič zo špecifikácie potichu nechýba alebo nie je len spolovice hotové.

Priprav tabuľku pokrytia: požiadavka z PRD -> implementované? (áno / čiastočne / nie) -> kde v kóde -> aká je medzera. Cituj konkrétne súbory. Označ všetko, čo je spravené inak, než hovorí špecifikácia, aj keď to funguje.
SEC03 / 07

Security audit

Bezpečnostný audit

A deep audit of what the code really does - not what the docs claim.

Hĺbkový audit toho, čo kód naozaj robí - nie čo tvrdí dokumentácia.

Prompt
Do a thorough, deep security audit of this application - frontend and backend. Check the real implementation in the code, not the docs, READMEs or comments. Verify actual behaviour.

Context: the app is internet-facing, behind an F5 (BIG-IP) login. Security still matters - assume an authenticated user may be hostile.

Cover at least:
- AuthN / AuthZ: is every endpoint properly protected? Any missing authorization checks (IDOR, privilege escalation, trusting the frontend to hide things)?
- Input validation and injection: SQL / NoSQL injection, command injection, XSS (stored and reflected), SSRF.
- Secrets: hardcoded credentials, tokens or keys in the repo or the client bundle.
- Data exposure: sensitive data sent to the client, verbose errors, PII in logs.
- Sessions and tokens: CSRF, secure cookies, CORS configuration.
- Dependencies with known vulnerabilities.
- OWASP Top 10 as a checklist.

For each finding: severity, exact file / line, how it could be exploited, and the concrete fix. Prioritise by real-world risk. Check the code - verify, don't assume.
Sprav dôkladný, hĺbkový bezpečnostný audit tejto aplikácie - frontend aj backend. Kontroluj reálnu implementáciu v kóde, nie dokumentáciu, README ani komentáre. Over skutočné správanie.

Kontext: aplikácia je otvorená do internetu, za loginom cez F5 (BIG-IP). Bezpečnosť je aj tak dôležitá - predpokladaj, že aj prihlásený používateľ môže byť nepriateľský.

Pokry aspoň:
- AuthN / AuthZ: je každý endpoint poriadne chránený? Nechýbajú niekde autorizačné kontroly (IDOR, eskalácia práv, spoliehanie sa na to, že to skryje frontend)?
- Validácia vstupov a injection: SQL / NoSQL injection, command injection, XSS (stored aj reflected), SSRF.
- Tajomstvá: natvrdo zapísané heslá, tokeny alebo kľúče v repozitári alebo v klientskom bundli.
- Únik dát: citlivé dáta posielané na klienta, ukecané chybové hlášky, PII v logoch.
- Session a tokeny: CSRF, secure cookies, nastavenie CORS.
- Závislosti so známymi zraniteľnosťami.
- OWASP Top 10 ako checklist.

Pri každom náleze: závažnosť, presný súbor / riadok, ako sa to dá zneužiť, a konkrétna oprava. Prioritizuj podľa reálneho rizika. Kontroluj kód - over, nepredpokladaj.
REFACTOR04 / 07

Refactoring analysis

Analýza refaktoringu

Cleaner, safer, more readable code - without changing a single behaviour.

Čistejší, bezpečnejší a čitateľnejší kód - bez zmeny akéhokoľvek správania.

Prompt
Review how this application is implemented and find what we can improve to make it more maintainable and readable - without changing any functionality. We are only improving the code, never the behaviour.

Look for:
- Readability: unclear naming, over-long functions, deep nesting.
- Change safety: code where a small edit is likely to break something unrelated.
- Open/Closed principle: places where extending behaviour forces us to modify existing code.
- Dead code: unused functions, variables, imports, unreachable branches.
- Scattered logic that belongs together - pull it into cohesive functions / modules.
- Copy&paste code: extract the shared abstraction into a single place.
- Magic strings and numbers: pull them into named constants, so we stop comparing raw strings in different spots.
- Typing: are the types correct and complete everywhere? Any "any", missing types, unsafe casts?
- Suppressed checks: disabled linter rules, ignored errors, skipped tests, eslint-disable, @ts-ignore. We want everything checked - flag every suppression.
- Missing comments where they'd genuinely help understanding (not noise).
- General code smells.

Deliver a complete analysis: what to change, why, and how - ranked by value. Do not change functionality; refactor only.
Pozri sa, ako je táto aplikácia naimplementovaná, a nájdi, čo vieme zlepšiť, aby bola lepšie udržiavateľná a čitateľnejšia - bez zmeny akejkoľvek funkcionality. Iba zlepšujeme kód, nikdy nie správanie.

Hľadaj:
- Čitateľnosť: nejasné pomenovania, príliš dlhé funkcie, hlboké zanorenie.
- Bezpečnosť zmien: kód, kde malá úprava pravdepodobne pokazí niečo nesúvisiace.
- Open/Closed princíp: miesta, kde rozšírenie správania núti meniť existujúci kód.
- Mŕtvy kód: nepoužité funkcie, premenné, importy, nedosiahnuteľné vetvy.
- Roztrúsenú logiku, ktorá patrí spolu - vytiahni ju do súdržných funkcií / modulov.
- Copy&paste kód: vytiahni spoločnú abstrakciu na jedno miesto.
- Magic strings a čísla: vytiahni ich do pomenovaných konštánt, nech neporovnávame surové reťazce sem-tam.
- Typovosť: sú typy všade správne a úplné? Nie je niekde "any", chýbajúce typy, nebezpečné pretypovania?
- Potlačené kontroly: vypnuté pravidlá lintera, ignorované chyby, preskočené testy, eslint-disable, @ts-ignore. Chceme kontrolovať všetko - označ každé potlačenie.
- Chýbajúce komentáre tam, kde by naozaj pomohli pochopeniu (nie šum).
- Všeobecné code smells.

Priprav kompletnú analýzu: čo zmeniť, prečo a ako - zoradené podľa prínosu. Nemeň funkcionalitu; iba refaktoruj.
UX05 / 07

Usability review

Revízia použiteľnosti

What's missing to make the app genuinely pleasant to use.

Čo chýba, aby bola appka naozaj príjemná na používanie.

Prompt
I want this app to be genuinely usable from a UX perspective. Review it and tell me what's missing and what we need to add to make it easier and more pleasant to use.

Consider:
- Clarity: is it always obvious what to do next? Labels, empty states, feedback after actions.
- Errors from the user's side: helpful messages, recovery paths, preventing mistakes before they happen.
- Consistency: patterns, wording and components used the same way throughout.
- Accessibility: keyboard navigation, visible focus, contrast, screen-reader labels, ARIA.
- Forms: when validation fires, sensible defaults, clearly marked required fields.
- Loading and latency: skeletons, optimistic UI, progress feedback.
- Mobile and responsive behaviour.

Give concrete, prioritised recommendations, and say where each one applies.
Chcem, aby bola táto aplikácia z pohľadu UX naozaj dobre použiteľná. Prejdi ju a povedz mi, čo chýba a čo potrebujeme doplniť, aby sa používala ľahšie a príjemnejšie.

Zváž:
- Zrozumiteľnosť: je vždy jasné, čo spraviť ďalej? Popisky, prázdne stavy, spätná väzba po akciách.
- Chyby z pohľadu používateľa: nápomocné hlášky, cesty z chyby von, predchádzanie omylom skôr, než nastanú.
- Konzistentnosť: vzory, formulácie a komponenty používané všade rovnako.
- Prístupnosť: ovládanie klávesnicou, viditeľný focus, kontrast, popisky pre čítačky obrazovky, ARIA.
- Formuláre: kedy sa spúšťa validácia, rozumné defaulty, jasne označené povinné polia.
- Načítavanie a odozva: skeletony, optimistické UI, indikácia priebehu.
- Mobil a responzívne správanie.

Daj konkrétne, prioritizované odporúčania a pri každom povedz, kde sa uplatní.
MODERN06 / 07

Modernization audit

Audit modernosti

How to get to a state-of-the-art implementation on our current stack.

Ako sa dostať k state-of-the-art implementácii na našom stacku.

Prompt
I want this to be a state-of-the-art, modern application, built the way apps of this type are built today. Audit it and propose how to get there.

- Modern patterns and architecture appropriate for an app like this.
- The frameworks we already use: are we on current versions and using their latest recommended patterns correctly (React - hooks, Suspense, data-fetching patterns, server components where they fit)?
- Dependencies: which packages are outdated, deprecated, or replaceable by a better modern option? Which strong current packages could we adopt to our benefit?
- Tooling: build, bundling, type-safety, testing, CI - is it current?
- Anything holding us back from being a modern reference implementation.

Deliver an audit plus a concrete, prioritised roadmap: what to upgrade or adopt, and in what order. Separate quick wins from risky migrations.
Chcem, aby toto bola state-of-the-art, moderná aplikácia, postavená tak, ako sa dnes robia appky tohto typu. Sprav audit a navrhni, ako sa k tomu dostať.

- Moderné postupy a architektúra vhodné pre appku tohto typu.
- Frameworky, ktoré už používame: sme na aktuálnych verziách a používame ich najnovšie odporúčané postupy správne (React - hooks, Suspense, vzory načítavania dát, server components tam, kde dávajú zmysel)?
- Závislosti: ktoré balíky sú zastarané, deprecated alebo nahraditeľné lepšou modernou alternatívou? Ktoré silné aktuálne balíky by sme vedeli využiť v náš prospech?
- Nástroje: build, bundling, typová bezpečnosť, testovanie, CI - je to aktuálne?
- Čokoľvek, čo nás brzdí byť modernou referenčnou implementáciou.

Priprav audit a konkrétny, prioritizovaný plán: čo upgradovať alebo zaviesť a v akom poradí. Oddeľ rýchle výhry od rizikových migrácií.
ENGAGE07 / 07

Engagement & behavioral design

Engagement a behaviorálny dizajn

Eleven behavioral levers that turn a used-once app into one people return to.

Jedenásť behaviorálnych pák, ktoré z appky na jedno použitie spravia appku, ku ktorej sa ľudia vracajú.

Prompt
Look at this application and find where we can improve it for the user and for engagement. Go through these behavioral-design lenses (skip any that don't fit - don't force them):

peak-end rule, Zeigarnik effect, goal-gradient + endowed progress, variable reward, flow, curiosity gap, aesthetic-usability, IKEA effect, fresh-start effect, Hick's law, loss aversion.

For each lens that fits: name the exact screen or flow, what's weak today, one concrete change, and roughly how hard it is to ship. Rank the ideas by impact-to-effort. Flag anything that would cross into a dark pattern and give me the ethical version instead.
Pozri sa na aplikáciu, kde ju vieme vylepšiť z pohľadu používateľa a engagementu. Prejdi ju cez tieto behaviorálne optiky (preskoč tie, čo nesadnú - nesiľ ich):

peak-end rule, Zeigarnik efekt, goal-gradient + endowed progress, variabilná odmena, flow, curiosity gap, aesthetic-usability, IKEA efekt, fresh-start efekt, Hickov zákon, loss aversion.

Pri každej optike, ktorá sadne: pomenuj konkrétnu obrazovku alebo flow, čo je dnes slabé, jednu konkrétnu zmenu a približne aké ťažké je to nasadiť. Zoraď nápady podľa pomeru dopad/námaha. Označ všetko, čo by prešlo do dark patternu, a daj mi namiesto toho etickú verziu.

The eleven lenses

Jedenásť optík

Peak-end ruleWe remember the peak and the ending, not the average. Build one wow moment, polish the last screen.Pamätáme si vrchol a koniec, nie priemer. Sprav jeden wow moment a dolaď posledný krok.
Zeigarnik effectUnfinished tasks nag us. Progress bars, "80% done", saved drafts - an open loop to close.Nedokončené úlohy nám vŕtajú v hlave. Progress bary, "hotové na 80%", uložené drafty.
Goal-gradientThe closer the goal, the harder we push. Start progress pre-filled ("2 of 5 done").Čím bližšie k cieľu, tým väčší ťah. Začni progres predvyplnený ("2 z 5 hotové").
Variable rewardUnpredictable rewards stick. An occasional surprise - but reward real value, not a slot machine.Nepredvídateľná odmena drží. Občasné prekvapenie - ale odmeňuj hodnotu, nie ako automat.
FlowEngagement lives just above current skill. Don't drown newcomers, don't bore power users.Engagement žije tesne nad schopnosťami. Neprehlť nováčika, nenuď power usera.
Curiosity gapA visible gap pulls us forward. "2 more steps and you'll see your result."Viditeľná medzera ťahá dopredu. "Ešte 2 kroky a uvidíš výsledok."
Aesthetic-usabilityNicer-looking things feel easier and more trustworthy. Polish is perceived quality.Krajšie veci pôsobia jednoduchšie a dôveryhodnejšie. Polish je vnímaná kvalita.
IKEA effectWe value what we helped build. Let users set something up in onboarding.Vážime si to, na čom sme sa podieľali. Nechaj usera si niečo nastaviť v onboardingu.
Fresh-start effectMotivation rises at symbolic beginnings. Let people restart without feeling they failed.Motivácia stúpa pri symbolických začiatkoch. Umožni reštart bez pocitu zlyhania.
Hick's lawMore options = slower decisions. Fewer choices per screen, sensible defaults, one primary action.Viac možností = pomalšie rozhodovanie. Menej volieb, rozumné defaulty, jedno hlavné CTA.
Loss aversionLosing hurts more than gaining. "Don't lose your streak" > "earn a point". Warn, don't coerce.Strata bolí viac než zisk poteší. "Nepríď o streak" > "získaj bod". Varuj, nevydieraj.
